## Что это за проект

Внутренняя **веб-система для мебельной компании**, объединяющая два направления:

1. **Учёт рабочего времени** — смены сотрудников, личный кабинет, админ-панель, графики, PDF-отчёты.
2. **Каталог и заказы мебели** — расчёт изделий по параметрам, оформление/редактирование заказов, просмотр заказов.

**Стек:** React 19 (CRA) + SCSS на фронте, Express 5 + PostgreSQL (Supabase) на бэкенде.

## Критические проблемы

### 1. Авторизация только на клиенте

Фронт загружает **всех пользователей с паролями** через `GET /users` и сверяет пароль в браузере через `bcryptjs`. Бэкенд уже умеет JWT (`/login`), но **не используется**.

В `src/Context.js` пароль логируется в консоль:

```js
console.log('Попытка входа:', identifier, password);
```

**Последствие:** любой может получить данные пользователей и обойти авторизацию.

### 2. API без защиты

Middleware `authenticate` есть (`backend/src/middleware/auth.js`), но **ни к одному маршруту не подключён**. Любой может читать/менять `users`, `workSessions`, `order` без токена.

### 3. Каталог недоступен обычным сотрудникам

В меню есть «Каталог мебели», но для `user` главная (`/`) редиректит в `/cabinet`:

```js
// src/App.js
element={
    currentUser?.role === 'admin'
        ? <Catalog />
        : <Navigate to="/cabinet" replace />
}
```

**Последствие:** обычный сотрудник никогда не увидит каталог, хотя пункт меню для него отображается.

### 4. Нет route guard

Неавторизованный пользователь может открыть `/cabinet`, `/view_orders` и т.д. — защита только локальная на отдельных страницах.

### 5. Сломанный `npm run server`

В корневом `package.json` указан `server.js`, файла нет (есть только `server.old.js`). Актуальный бэкенд — в `backend/app.js`.

## Архитектурный разрыв

Проект в **переходном состоянии**:

| Было | Стало | Проблема |
|------|-------|----------|
| json-server + lowdb | PostgreSQL + Express | Старые зависимости в корневом `package.json` |
| Клиентский auth | JWT на бэкенде | Фронт не переключён |
| Единый UI | `legacy/` + новые страницы | Два стиля, 36 `alert`/`confirm` в 5 файлах |
| `order_editor` | `placing_an_order` | Дублирование логики заказов |

**Жёстко прошитый API:** `http://localhost:8080` в 7+ файлах, нет `REACT_APP_API_URL`.

**Дублирование утилит:** `calculateShiftDuration` / `formatDuration` скопированы в `Context.js`, `admin.js`, `cabinet.js`.

**Сломанная ссылка логотипа:** в `header.js` логотип ведёт на `/home`, такого маршрута в `App.js` нет.

**Рассинхрон редиректов после логина:**

| Роль | После логина (`auth.js`) | Index-роут (`App.js`) |
|------|--------------------------|------------------------|
| admin | `/edit_mebel` | `<Catalog />` |
| user | `/` → редирект в `/cabinet` | — |

## База данных

Схема (из `backend/migrate_beautiful.js`):

- **users** — email, password, login, fullName, avatar, role, badgeId
- **workSessions** — userId, date, startTime, endTime, durationMinutes, status
- **product** — img, title, variables/conditions/details (JSONB), price
- **order** — клиент, адрес, product_order (JSONB), суммы, status

Есть два миграционных скрипта: старый (`JSONB data` в `migrate.js`) и актуальный (реляционные колонки в `migrate_beautiful.js`).
